# FeriasFlow - Calendario API<br/><br/>API **secundaria** do MVP da Sprint *Arquitetura de Software* (pos-graduacao em Engenharia de<br/>Software, PUC-Rio). Servico de calendario de trabalho: cadastra **feriados locais**, consulta os<br/>**feriados nacionais** na [BrasilAPI](https://brasilapi.com.br) e conta os **dias uteis** de um<br/>periodo. E consumida pela API principal<br/>[`feriasflow-api`](https://github.com/FSEB-SW/feriasflow-api), que gerencia pedidos de ferias.<br/><br/>| Componente | Repositorio | Papel |<br/>|---|---|---|<br/>| API principal | [FSEB-SW/feriasflow-api](https://github.com/FSEB-SW/feriasflow-api) | pedidos de ferias, colaboradores, decisao do gestor; `docker-compose.yml` |<br/>| API secundaria | **este repositorio** | feriados locais + dias uteis |<br/>| API externa | [BrasilAPI - Feriados Nacionais](https://brasilapi.com.br/docs#tag/Feriados-Nacionais) | `GET /feriados/v1/{ano}`, publica e gratuita, sem cadastro |<br/><br/>Aluno: Julio Frois. Continuidade do produto **FeriasFlow** idealizado na Sprint de Gestao Agil<br/>([FSEB-SW/ferias-flow-mvp](https://github.com/FSEB-SW/ferias-flow-mvp)).<br/><br/>## Por que um servico separado<br/><br/>O dominio "calendario de trabalho" tem **coesao propria** (feriados, dias uteis) e **ciclo de vida<br/>independente** do dominio "pedido de ferias": o RH atualiza feriados uma vez por ano; pedidos mudam<br/>todo dia. Separar da a API principal um consumidor claro (`GET /dias-uteis`) e isola a dependencia<br/>externa (BrasilAPI) num unico lugar, com cache e disjuntor. O trade-off (um salto de rede a mais,<br/>dois deploys) esta registrado no README da API principal, em *Decisoes de arquitetura*.<br/><br/>## Fluxo<br/><br/>```mermaid<br/>flowchart LR<br/>    P[feriasflow-api\nAPI principal] -- "GET /dias-uteis?inicio&fim" --> C<br/>    subgraph C[feriasflow-calendario-api]<br/>        direction TB<br/>        R[Rotas FastAPI] --> S[services.calcular_dias_uteis]<br/>        S --> DB[(SQLite\nferiados locais)]<br/>        S --> B[brasilapi.py\ncache por ano + disjuntor]<br/>    end<br/>    B -- "GET /feriados/v1/{ano}" --> X[BrasilAPI\nAPI externa]<br/>    X -. "falha / timeout" .-> B<br/>    B -. "fonte_nacional = cache ou indisponivel" .-> S<br/>```<br/><br/>Se a BrasilAPI falhar, a resposta continua **200** com `fonte_nacional: "indisponivel"` e um<br/>`aviso`: o servico degrada de forma controlada em vez de derrubar quem depende dele. Apos 3 falhas<br/>seguidas o disjuntor abre por 60 s e o servico para de insistir na fonte externa.<br/><br/>## Rotas<br/><br/>| Metodo | Rota | Descricao |<br/>|---|---|---|<br/>| GET | `/feriados?ano=` | lista feriados locais (filtro opcional por ano) |<br/>| GET | `/feriados/{id}` | obtem um feriado |<br/>| POST | `/feriados` | cadastra feriado local (`data`, `nome`, `tipo` = municipal, estadual ou empresa) |<br/>| PUT | `/feriados/{id}` | atualiza (parcial) |<br/>| DELETE | `/feriados/{id}` | remove |<br/>| GET | `/dias-uteis?inicio=&fim=` | dias corridos, fins de semana, feriados (locais + nacionais) e dias uteis |<br/>| GET | `/feriados-nacionais/{ano}` | repasse dos feriados nacionais da BrasilAPI |<br/>| GET | `/health` | estado do servico, do banco e da BrasilAPI |<br/><br/>Documentacao interativa (Swagger): `http://localhost:8001/docs`. Codigos: 201 criado, 204 removido,<br/>404 nao encontrado, 409 data ja cadastrada, 422 entrada invalida.<br/><br/>Exemplo:<br/><br/>```<br/>GET /dias-uteis?inicio=2026-09-01&fim=2026-09-30<br/>{<br/>  "inicio": "2026-09-01", "fim": "2026-09-30",<br/>  "dias_corridos": 30, "dias_uteis": 21, "fins_de_semana": 8,<br/>  "feriados": [{"data": "2026-09-07", "nome": "Independencia do Brasil", "origem": "nacional"}],<br/>  "fonte_nacional": "brasilapi", "aviso": null<br/>}<br/>```<br/><br/>## API externa: BrasilAPI<br/><br/>- Endpoint: `https://brasilapi.com.br/api/feriados/v1/{ano}`; sem autenticacao, sem custo, licenca MIT.<br/>- Documentacao: <https://brasilapi.com.br/docs#tag/Feriados-Nacionais>.<br/>- Resposta: `[{"date": "2026-04-21", "name": "Tiradentes", "type": "national"}, ...]`.<br/>- Uso aqui: `app/brasilapi.py` consulta por ano, guarda em cache (24 h) e aplica timeout de 5 s.<br/>  Configuravel por `BRASILAPI_URL`, `BRASILAPI_TIMEOUT`, `BRASILAPI_CACHE_TTL`,<br/>  `BRASILAPI_FALHAS_PARA_ABRIR`, `BRASILAPI_TEMPO_ABERTO`.<br/><br/>## Como executar<br/><br/>Com Docker (recomendado):<br/><br/>```bash<br/>docker build -t feriasflow-calendario-api .<br/>docker run --rm -p 8001:8000 -v feriasflow_calendario:/app/data feriasflow-calendario-api<br/>```<br/><br/>Acesse `http://localhost:8001/docs`. O volume guarda o SQLite entre execucoes. Para subir os dois<br/>servicos juntos use o `docker-compose.yml` da API principal.<br/><br/>Sem Docker (Python 3.12):<br/><br/>```bash<br/>python -m venv .venv && .venv\Scripts\activate    # Windows; no Linux: source .venv/bin/activate<br/>pip install -r requirements.txt<br/>uvicorn app.main:app --reload --port 8001<br/>```<br/><br/>Variaveis: `DATABASE_URL` (padrao `sqlite:///./data/calendario.db`).<br/><br/>## Testes<br/><br/>```bash<br/>pip install -r requirements-dev.txt<br/>pytest -q<br/>```<br/><br/>Vinte testes, sem rede (a BrasilAPI e simulada com `httpx.MockTransport`):<br/><br/>- CRUD de feriados (201/200/204/404/409/422);<br/>- contagem de dias uteis com fim de semana, feriado nacional, feriado local e virada de ano;<br/>- cache, degradacao com a BrasilAPI fora e abertura do disjuntor;<br/>- **teste de contrato** (`tests/test_contrato.py`): a resposta de `/dias-uteis` e validada contra<br/>  `contratos/dias-uteis.schema.json`, o mesmo arquivo que o consumidor (`feriasflow-api`) usa do<br/>  lado dele. Quem mudar o formato quebra o teste antes de quebrar o consumidor.<br/><br/>## Pipeline (GitHub Actions)<br/><br/>`.github/workflows/ci.yml`: a cada push ou pull request roda `pytest`, constroi a imagem Docker e<br/>sobe o container para conferir o `/health` (smoke test). Entrega por pull request.<br/><br/>## Estrutura<br/><br/>```<br/>app/<br/>  main.py          aplicacao FastAPI e rotas montadas<br/>  config.py        variaveis de ambiente<br/>  database.py      engine/sessao SQLAlchemy (SQLite)<br/>  models.py        agregado Feriado<br/>  schemas.py       contratos Pydantic de entrada/saida<br/>  brasilapi.py     cliente da API externa (cache + disjuntor)<br/>  services.py      calculo de dias uteis<br/>  routers/         feriados.py, calendario.py, health.py<br/>contratos/         dias-uteis.schema.json (contrato compartilhado com o consumidor)<br/>tests/             pytest (fixtures sem rede)<br/>Dockerfile         imagem python:3.12-slim, usuario sem privilegio, HEALTHCHECK<br/>```<br/>
